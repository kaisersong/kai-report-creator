# 自评（对抗视角）— two-new-themes v1

## 1) 假设漏洞

1. **「辨识度一致」验收不可判**：§4 用「用户主观确认」做 Phase 1 验收，没有并排
   对照物与检查清单。反例：AI 渲染时把 hero 深色带渲成普通 h1 标题区，样张
   仍然「好看」，用户看不出丢了锚区，验收形同虚设。
2. **自定义主题的「零校验」是双刃剑**：gate 对未知主题名跳过指纹校验（方案自己
   §3.2 也承认），意味着 Phase 1 里 AI 手写 HTML 时哪怕完全无视 theme.css 的
   变量、自创一套配色，gate 也报 valid。反例：AI 直接内联 `#0b6b55` 的近似色
   `#0a6假设`，没有任何机制发现。
3. **radar-board 的差异化判断依赖「肉眼对比」**：§5 R2 说样张阶段并排对比，但
   没定义谁判、按什么维度判。反例：换个屏幕色温，dark-board 和 radar-board 的
   `#12161d` vs `#161A20` 底色根本分不出来，降级触发条件永远不成立。

## 2) 新风险/回归

1. **主题表通胀**：8→10 个内置主题，theme-routing 的自动选择规则每加一个主题
   判别难度超线性上升；routing 写不好会把普通商务报告错路由到 radar-board。
2. **`--themes` 预览维护成本**：预览 HTML 是手工产物（skill 不解析内部），加两
   主题就要重新生成整页，容易漏，造成 README/预览/实际主题三者不同步。
3. **forest 的 color-mix()**：源文件用了 `color-mix(in srgb, ...)`，在导出
   PNG 的 headless 老内核或某些邮件客户端里不支持，静默降级成无 outline/边框。

## 3) 更简替代

1. **只做 forest-editorial**：radar-board 与 dark-board 的实质差异（mono 栈 +
   单 accent）用 `theme_overrides` + 一段 POST-SHARED 片段即可表达，独立主题
   性价比低——先做 overrides 预设文档化，够用就不立项。
2. **Phase 1 验收改为「三点硬检查」**：hero 深色带存在（`--navy` 背景块）、
   KPI 值命中 `--green`、无外部字体请求——脚本可查，不靠主观。

## 4) 只做一件事

先做 forest-editorial 的 Phase 1 样张（含三点硬检查）。它差异化最明确、
不依赖会下线的外部站点，且能立刻验证「自定义主题 + AI 手写渲染」这条路的
保真度——这是整个方案成立与否的前提。
